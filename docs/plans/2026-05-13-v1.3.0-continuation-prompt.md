### Task DA-01: `DB::afterCommit` for event dispatch (13 sites)

**Goal**: Move `Event::dispatch(...)` and `Queue::dispatch(...)` calls out of `DB::transaction(...)` closures so listeners never fire side-effects (emails, notifications, license-state updates) when the transaction rolls back.

**Why deferred**: The advisor flagged this as a semantic change. Some listeners may legitimately rely on pre-commit DB visibility (rare but real, e.g., audit listeners that want to see the in-flight state). Listener audit must precede the change.

**Pre-work (do this first)**:

```bash
grep -rn "Event::listen\|protected \$listen\|EventServiceProvider" src/
grep -rn "implements ShouldQueue.*Listen\|Listener" src/
```

**Listeners I found in v1.2.0 (incomplete — re-audit)**:

- `LicenseLifecycleListener` (`src/Licensing/Listeners/LicenseLifecycleListener.php`) registered in `LaravelSubscriptionGuardServiceProvider::registerLicenseLifecycleListeners()` for: `SubscriptionCreated`, `PaymentCompleted`, `PaymentFailed`, `SubscriptionRenewed`, `SubscriptionRenewalFailed`, `SubscriptionCancelled`. This is the **only** package-internal listener I found.

**Action**: read `LicenseLifecycleListener` and decide per-event whether `afterCommit` is safe. License lifecycle listeners typically want post-commit (so the new subscription/payment row exists) — likely safe to wrap.

**13 dispatch sites in `src/Subscription/SubscriptionService.php`** (line numbers from `main` post-v1.2.0 — verify with `grep -n "Event::dispatch\|DispatchBillingNotificationsJob::dispatch" src/Subscription/SubscriptionService.php` before editing):

- Webhook `subscription.created`: `SubscriptionCreated` + provider dispatch

- `handlePaymentResult` success: `PaymentCompleted`, `SubscriptionRenewed`, provider dispatch, `DispatchBillingNotificationsJob`
- `handlePaymentResult` failure: `PaymentFailed`, `SubscriptionRenewalFailed`, provider dispatch, `DispatchBillingNotificationsJob`
- `recordWebhookTransaction` success: `PaymentCompleted`, `SubscriptionRenewed`, provider dispatch
- `recordWebhookTransaction` failure: `PaymentFailed`, `SubscriptionRenewalFailed`, provider dispatch

**Implementation pattern**:

### Task DA-02: Iyzico `cancelSubscription` "already cancelled" idempotency

**Goal**: `IyzicoProvider::cancelSubscription()` currently returns `false` for any non-success response. If iyzico reports "subscription not found" or "already cancelled", the package treats it as a failure and `SubscriptionService::cancel()` aborts. The remote sub is gone but local state stuck. Need to map these specific error codes to `true`.

**Why deferred**: The proposed error code mapping in the v1.2.0 plan (`['1', '200001', '200002']`) was **guessed**. Must be confirmed from `vendor/iyzico/iyzipay-php/samples/` or a live sandbox round-trip before merging.

**Pre-work**:

```bash
ls vendor/iyzico/iyzipay-php/samples/ | grep -i subscript
grep -rn "errorCode\|getErrorCode\|cancelSubscription" vendor/iyzico/iyzipay-php/ | head -30
```

OR live sandbox round-trip:

```bash
export RUN_IYZICO_LIVE_SANDBOX_TESTS=true
export IYZICO_MOCK=false
export IYZICO_API_KEY=...
export IYZICO_SECRET_KEY=...
export IYZICO_BASE_URL=https://sandbox-api.iyzipay.com
composer test-live -- --filter="cancelSubscription"
```

Call cancel twice on the same subscription, inspect the second response for the exact `errorCode` / `errorMessage`.

**Action**:

In `src/Payment/Providers/Iyzico/IyzicoProvider.php:257-278`, wrap the success check with an `isAlreadyCancelledError()` helper:

```php
public function cancelSubscription(string $subscriptionId): bool
{
    if (! $this->mockMode()) {
        if ($subscriptionId === '' || $this->missingCredentials() !== []) {
            return false;
        }

        try {
            $request = new SubscriptionCancelRequest;
            $request->setConversationId('iyz_cancel_'.bin2hex(random_bytes(8)));
            $request->setSubscriptionReferenceCode($subscriptionId);

            $response = SubscriptionCancel::cancel($request, $this->options());

            if ($this->isSuccessfulResponse($response)) {
                return true;
            }

            // Map "already cancelled / not found" to idempotent success.
            $errorCode = method_exists($response, 'getErrorCode') ? (string) $response->getErrorCode() : '';
            $errorMessage = strtolower($this->responseError($response, ''));

            if ($this->isAlreadyCancelledError($errorCode, $errorMessage)) {
                return true;
            }

            return false;
        } catch (Throwable) {
            return false;
        }
    }

    return $subscriptionId !== '';
}

private function isAlreadyCancelledError(string $errorCode, string $errorMessage): bool
{
    // Replace with confirmed codes from sandbox / vendor inspection:
    $alreadyCancelledCodes = [/* confirmed codes go here */];
    $alreadyCancelledFragments = ['not found', 'already cancelled', 'already canceled', 'cancelled before'];

    if (in_array($errorCode, $alreadyCancelledCodes, true)) {
        return true;
    }

    foreach ($alreadyCancelledFragments as $fragment) {
        if (str_contains($errorMessage, $fragment)) {
            return true;
        }
    }

    return false;
}
```

Create a stub iyzico response object (or partial double) that returns the "already cancelled" error code, inject via container binding, assert `IyzicoProvider::cancelSubscription` returns `true` AND `SubscriptionService::cancel()` converges the local state to `Cancelled`.

**Branch**: `feat/iyzico-cancel-already-cancelled-idempotency`

### Task DA-03 (optional, low priority): Subscription model `transitionTo` silent fallback

**Goal**: `src/Models/Subscription.php:92-115` `transitionTo()` silently falls back to `setAttribute('status', $newStatus->value)` when `SubscriptionStatus::normalize()` returns `null`. This means any raw string status that isn't in the enum bypasses the state machine entirely.

**Why deferred**: Advisor flagged in final v1.2.0 review. v1.2.0 fixed the symptom (added `Trialing` enum case), but the silent fallback **mechanism** still exists. If anyone later adds a raw-string status (or removes a case from `normalize()` without updating callers), the bypass returns silently.

**Action**: Replace the silent fallback with a thrown exception or a logged + rejected transition:

```php
if (! $currentStatus instanceof SubscriptionStatus) {
    throw new SubGuardException(sprintf(
        'Cannot transition from unknown status "%s" on subscription #%s (%s → %s). '.
        'Add the status to SubscriptionStatus::normalize() before transitioning.',
        $currentStatusValue,
        (string) $this->getKey(),
        $currentStatusValue,
        $newStatus->value,
    ));
}
```

**Risk**: This is a behaviour change. Any existing data with an unknown raw-string status (left from old migrations or external writes) will start throwing. Run a one-shot SQL audit before merging:

```sql
SELECT DISTINCT status FROM subscriptions;
SELECT DISTINCT status FROM licenses;
```

If unexpected values exist, decide: backfill them via migration, or extend the enum.

**Test strategy** — `tests/Feature/PhaseFourteenTransitionToStrictnessTest.php`:

Create a subscription, manually set status to a raw string not in the enum (via `DB::table()->update()`), call `transitionTo`, assert `SubGuardException` is thrown.

**Branch**: `feat/transition-to-strict-fallback`
